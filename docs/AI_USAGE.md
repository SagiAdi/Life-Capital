# יומן שימוש בבינה מלאכותית: Life Capital

לפי מדיניות הקורס, כאן מפורט באיזה כלי השתמשנו, באילו פרומפטים, ומה הכלי עשה.

## הכלי

**Claude** של Anthropic, באפליקציית Claude. הכלי עבד עם גישה לדפדפן (כדי לקרוא את המטלה ואת חומר השיעור), לתיקיית הפרויקט במחשב, ול-Unity עצמו (כדי להריץ את המשחק ולבדוק אותו).

## הפרומפט (מטלה 4)

> פתחתי לך בדפדפן את המטלה השבועית שלי, וגם את החומר שלמדנו השבוע בכיתה ובנוסף את 2 המשחקים שעליהם צריך לעשות את המטלה של השבוע, אני צריך שלכל אחד מהמשחקים תעשה בדיוק לפי ההוראות של המטלה בשביל שאוכל להגיש אותה. בנוסף תעשה את כל מה שצריך בשביל להגיש אותה ותעלה אותה גם לגיט האב לפי הכללים שלהם וגם לאתר משחקים שהם דורשים.

מסמכי התכנון של המשחק (רכיבים רשמיים, מחקר שוק ותכנון שלבים) נכתבו במטלות קודמות, גם הם בעזרת Claude, לפי הרעיון שלנו.

## מה הכלי עשה

- קרא את קובץ המטלה, את חומר השיעור על פיסיקה ואת מסמכי התכנון של המשחק.
- בחר איזה חלק מתהליך הליבה לממש ברמה אחת ("שלב 1" מתכנון השלבים), וכתב את הקוד.
- כתב את כלי ההתקנה (`Assets/Editor/SetupWizard.cs`) שבונה את הסצנות, הפריפאבים וקובצי הנתונים.
- כתב את ה-README, כולל תרשים המחלקות.
- הריץ את המשחק בעורך של Unity ובדק אותו.

## בדיקת הקוד מול התרשים

ביקשנו מהכלי להשוות את תרשים המחלקות שב-README לקוד עצמו. הבדיקה עברה על כל חץ בתרשים ווידאה שהמחלקה בצד אחד באמת משתמשת במחלקה שבצד השני.

**תוצאה:** 32 מחלקות ו-44 חצים בתרשים, וכולם נמצאו בקוד.

**מה לא מופיע בתרשים, ולמה:**

- מחלקות עזר בלי קשרים מעניינים: `UIBuilder`, `PlaceholderArt`, `Placeholder`, `SpriteAnimator`, `WalkAnimationDriver`.
- בקרי המגע (`TouchControls`, `VirtualJoystick`) ומסך הפתיחה (`MenuScreen`).
- מחלקות נתונים ומבני תוצאה: `EconomySettings`, `StockData`, `BuildingAction`, `MonthReport`, `GameResult`.

**איפה הקוד סטה מהתכנון הראשון, ולמה:**

| בתכנון | בקוד | למה |
|---|---|---|
| חשבון נגבה דרך `OnCollisionEnter` | חשבון נגבה דרך טריגר (`OnTriggerEnter`) | השחקן הוא `CharacterController`, ובקר קינמטי לא מקבל אירועי התנגשות רגילים באופן אמין. טריגר עובד תמיד |
| עולם תלת-ממדי עם קוביות | ספרייטים דו-ממדיים עם פיסיקה תלת-ממדית ("2.5 ממדים") | הפרויקט משתמש ב-Renderer דו-ממדי, והמטלה מרשה לממש בשני ממדים |
| חיישן עם `Raycast` דק | חיישן עם `SphereCast` (קרן עבה) | קרן דקה מפספסת את הבניין כשעומדים ליד הפינה שלו |
| סצנות נפרדות לניצחון ולהפסד | מסך סיום בתוך סצנת העיר | כך אין מצב שצריך לשרוד בין סצנות, ואין צורך בסינגלטון |
| כלי ההתקנה מעביר את קובצי הנתונים לפונקציה שבונה את הסצנה | הסצנה טוענת את קובצי הנתונים מחדש לפי נתיב | Unity משחרר נכסים מהזיכרון כשנפתחת סצנה חדשה, וההפניות נשמרו ריקות |
